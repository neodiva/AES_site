01 · Selected research direction

Proposed project direction: Configurable RISC-V AES accelerator built around reusable GF arithmetic, evaluated through a PPA × security design-space exploration.

This is not presented as an already-proven novel invention. It is the research direction selected from the site's novelty hub because it combines several gaps already identified there instead of stopping at another S-box-only optimization.

Baseline

Iterative AES-128 encryption engine with a LUT S-box, one round per cycle, explicit key schedule and a small accelerator control interface.

Research upgrade A

Replace the LUT S-box with a composite/tower-field implementation and expose the GF arithmetic as a reusable internal engine.

Research upgrade B

Introduce configurable sharing/pipelining modes. Measure area, Fmax, latency, throughput and dynamic power for each configuration.

Research upgrade C

Add a defined side-channel evaluation plan. Report the attack model, traces, leakage metric and overhead rather than claiming universal security.

Positioning logic from your novelty hub: S-box-only optimization is crowded; RISC-V AES acceleration and shared AES engines already exist; reusable GF arithmetic, PPA/security interaction and architecture-level automation remain useful axes to combine.

06 · Step 3 — understand the exact CV32E40P boundary

The core exposes separate instruction and data memory interfaces. The important signals for the first integration are:

Instruction:
  instr_req_o
  instr_gnt_i
  instr_rvalid_i
  instr_addr_o
  instr_rdata_i

Data:
  data_req_o
  data_gnt_i
  data_rvalid_i
  data_addr_o
  data_we_o
  data_be_o
  data_wdata_o
  data_rdata_i
Key architectural fact: CV32E40P uses OBI-style memory interfaces. Vivado's AXI ecosystem does not make these ports magically become AXI. Your integration layer must perform the protocol conversion.

07 · Step 4 — make a minimal CPU memory system BEFORE AES

Build this first:

                    +----------------------+
                    |      CV32E40P        |
                    |   4-stage RISC-V      |
                    +-----------+----------+
                                |
                  +-------------+-------------+
                  |                           |
              instr OBI                    data OBI
                  |                           |
                  v                           v
          +---------------+           +---------------+
          | instruction   |           | data memory   |
          | memory model  |           | / peripheral  |
          +---------------+           +---------------+

For simulation, use a behavioral memory model. Your first pass does not need AXI at all. The objective is simply: reset → fetch → execute a tiny program → load/store → halt or signal PASS.

Checkpoint A: If the CPU cannot fetch and execute from an OBI memory model, stop here. Do not debug AXI and AES simultaneously.

09 · Step 6 — baseline AES-128 encryption RTL

This is the baseline, not the final novelty. It is deliberately simple so that the later research modifications have a measurable reference.

Architecture: initial AddRoundKey + 10 AES rounds; one round is processed per clock while busy; the final round omits MixColumns. The interface can later sit behind an AXI4-Lite register file.

  function automatic [7:0] rcon(input integer r);
    begin
      case (r)
        1:  rcon = 8'h01;
        2:  rcon = 8'h02;
        3:  rcon = 8'h04;
        4:  rcon = 8'h08;
        5:  rcon = 8'h10;
        6:  rcon = 8'h20;
        7:  rcon = 8'h40;
        8:  rcon = 8'h80;
        9:  rcon = 8'h1b;
        10: rcon = 8'h36;
        default: rcon = 8'h00;
      endcase
    end
  endfunction

  function automatic [7:0] gm2(input [7:0] a);
    gm2 = {a[6:0],1'b0} ^ (8'h1b & {8{a[7]}});
  endfunction

  function automatic [7:0] gm3(input [7:0] a);
    gm3 = gm2(a) ^ a;
  endfunction

  function automatic [127:0] sub_bytes(input [127:0] s);
    integer i;
    begin
      for (i = 0; i < 16; i = i + 1)
        sub_bytes[127-8*i -: 8] = sbox(s[127-8*i -: 8]);
    end
  endfunction

  // AES state is column-major: byte index = 4*column + row.
  function automatic [127:0] shift_rows(input [127:0] s);
    integer r, c, src_idx, dst_idx;
    begin
      for (c = 0; c < 4; c = c + 1) begin
        for (r = 0; r < 4; r = r + 1) begin
          src_idx = 4*((c+r)%4) + r;
          dst_idx = 4*c + r;
          shift_rows[127-8*dst_idx -: 8] = s[127-8*src_idx -: 8];
        end
      end
    end
  endfunction

  function automatic [127:0] mix_columns(input [127:0] s);
    integer c;
    reg [7:0] a0, a1, a2, a3;
    reg [7:0] b0, b1, b2, b3;
    begin
      for (c = 0; c < 4; c = c + 1) begin
        a0 = s[127-8*(4*c+0) -: 8];
        a1 = s[127-8*(4*c+1) -: 8];
        a2 = s[127-8*(4*c+2) -: 8];
        a3 = s[127-8*(4*c+3) -: 8];

        b0 = gm2(a0) ^ gm3(a1) ^ a2 ^ a3;
        b1 = a0 ^ gm2(a1) ^ gm3(a2) ^ a3;
        b2 = a0 ^ a1 ^ gm2(a2) ^ gm3(a3);
        b3 = gm3(a0) ^ a1 ^ a2 ^ gm2(a3);

        mix_columns[127-8*(4*c+0) -: 8] = b0;
        mix_columns[127-8*(4*c+1) -: 8] = b1;
        mix_columns[127-8*(4*c+2) -: 8] = b2;
        mix_columns[127-8*(4*c+3) -: 8] = b3;
      end
    end
  endfunction

  function automatic [31:0] sub_word(input [31:0] w);
    begin
      sub_word = {sbox(w[31:24]), sbox(w[23:16]), sbox(w[15:8]), sbox(w[7:0])};
    end
  endfunction

  function automatic [31:0] rot_word(input [31:0] w);
    rot_word = {w[23:0], w[31:24]};
  endfunction

  function automatic [127:0] next_round_key(
      input [127:0] key,
      input [7:0] rc);
    reg [31:0] w0, w1, w2, w3;
    reg [31:0] n0, n1, n2, n3;
    reg [31:0] t;
    begin
      w0 = key[127:96];
      w1 = key[95:64];
      w2 = key[63:32];
      w3 = key[31:0];

      t  = sub_word(rot_word(w3)) ^ {rc,24'h0};
      n0 = w0 ^ t;
      n1 = w1 ^ n0;
      n2 = w2 ^ n1;
      n3 = w3 ^ n2;

      next_round_key = {n0,n1,n2,n3};
    end
  endfunction

  logic [127:0] sb_sr_mc;
  logic [127:0] final_state;
  logic [127:0] key_next;

  always_comb begin
    key_next  = next_round_key(round_key_q, rcon(round_q));
    sb_sr_mc  = mix_columns(shift_rows(sub_bytes(state_q)));
    final_state = shift_rows(sub_bytes(state_q)) ^ key_next;
  end

  always_ff @(posedge clk or negedge rst_ni) begin
    if (!rst_ni) begin
      state_q     <= 128'b0;
      round_key_q <= 128'b0;
      round_q     <= 4'd0;
      block_o     <= 128'b0;
      busy_o      <= 1'b0;
      done_o      <= 1'b0;
    end else begin
      done_o <= 1'b0;

      if (start_i && !busy_o) begin
        state_q     <= block_i ^ key_i;  // AES AddRoundKey
        round_key_q <= key_i;
        round_q     <= 4'd1;
        busy_o      <= 1'b1;
      end else if (busy_o) begin
        if (round_q < 4'd10) begin
          state_q     <= sb_sr_mc ^ key_next;
          round_key_q <= key_next;
          round_q     <= round_q + 4'd1;
        end else begin
          block_o     <= final_state;
          state_q     <= final_state;
          round_key_q <= key_next;
          busy_o      <= 1'b0;
          done_o      <= 1'b1;
          round_q     <= 4'd0;
        end
      end
    end
  end
endmodule

    .key_i(key_i),
    .block_i(block_i),

12 · Step 9 — the OBI → AXI conversion

Do not treat this as a wire rename. OBI and AXI have different handshake semantics. Build a small transaction FSM.

CV32E40P
  |
  | data_req_o, data_addr_o, data_we_o,
  | data_be_o, data_wdata_o
  v
+-----------------------------+
|       OBI → AXI4-Lite       |
|                             |
| IDLE                        |
|  ↓                          |
| CAPTURE OBI REQUEST         |
|  ↓                          |
| WRITE: AW + W → B           |
| READ : AR → R               |
|  ↓                          |
| DRIVE OBI GNT / RVALID      |
+--------------+--------------+
               |
               v
        AXI4-Lite master
               |
        +------+------+
        | AXI SmartConnect
        +------+------+
               |
       +-------+---------+
       |       |         |
      BRAM    AES       UART
     ctrl     IP         IP

For the first version, use a single-outstanding-transaction bridge. That dramatically reduces the state space.

OBI conceptBridge action
data_req_o=1Capture one request when the bridge is idle.
data_addr_oDrive AXI address.
data_we_o=1AXI write transaction.
data_be_oAXI WSTRB.
data_wdata_oAXI WDATA.
AXI BVALIDReturn completion to OBI.
AXI RVALID/RDATAReturn read completion/data to OBI.
Research-quality requirement: add assertions for “one request captured at a time”, correct byte strobes, no lost response, and no OBI completion before the corresponding AXI response.

Instruction path: keep it separate initially. Use an instruction-memory adapter/bridge and a BRAM-backed instruction memory. Once the system works, optimize instruction fetch with AXI4 rather than forcing every fetch through AXI4-Lite.

13 · Step 10 — memory map for the AES accelerator

Use a simple 32-bit AXI4-Lite register interface. One possible map:

AddressRegisterUse
0x00CTRLbit 0 = START
0x04STATUSbit 0 = BUSY, bit 1 = DONE
0x10–0x1CKEY0–KEY3128-bit AES key
0x20–0x2CDATA0–DATA3128-bit plaintext
0x30–0x3COUT0–OUT3128-bit ciphertext
0x40CONFIGFuture mode selection: sharing/pipeline/security mode

When software writes START, the AXI wrapper produces a one-cycle start_i pulse for the AES core. When done_o rises, STATUS.DONE becomes visible and the result registers contain the ciphertext.
